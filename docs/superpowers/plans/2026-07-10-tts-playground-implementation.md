# TTS Playground Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Build and launch an authenticated internal API that routes low-cost synthesis to CPU-hosted Supertonic 3 and high-quality CustomVoice, VoiceDesign, and voice-clone synthesis to a single lazy-loading Qwen3-TTS 1.7B GPU worker.

**Architecture:** A FastAPI gateway is the only published service. It validates a stable OpenAI-shaped API and proxies to a private Qwen worker or the official Supertonic server. The Qwen worker owns model switching, bounded serialization, VRAM protection, idle unload, and persistent reference-voice storage.

**Tech Stack:** Python 3.12, FastAPI 0.139.0, Pydantic Settings 2.14.2, HTTPX 0.28.1, Prometheus Client 0.25.0, Structlog 26.1.0, pytest 9.1.1, qwen-tts 0.1.1, PyTorch/Torchaudio 2.11.0 CUDA 12.8 wheels, Supertonic 1.3.1, uv, Docker Compose.

## Global Constraints

- Keep all source and committed files inside /home/harim/develop/tts-playground; runtime caches and registered voices may be created only under the approved /srv/tts-cache and /srv/tts-data paths.
- Keep public model IDs exactly: supertonic-3, qwen3-tts-1.7b-custom, qwen3-tts-1.7b-design, qwen3-tts-1.7b-clone.
- Publish only the gateway on 0.0.0.0:8020; never publish worker ports.
- Keep at most one Qwen checkpoint resident and one Qwen generation active.
- Allow at most three waiting Qwen requests, wait 180 seconds, use a 360-second upstream timeout, unload after 600 idle seconds, require 10 GiB free before load, and use a 30-second error cooldown.
- Return WAV only. Accept synthesis text of 1-2,000 characters, instructions of 1-1,000, voice names up to 100, transcripts up to 4,000, and clone audio of 3-30 seconds and no more than 20 MB.
- Never stop, restart, signal, or reconfigure llama.cpp.
- Never log text, instructions, transcripts, audio, bearer tokens, or generated audio.
- Store model caches under /srv/tts-cache and registered voices under /srv/tts-data.
- Run tests before implementation for every behavior and commit each independently reviewable task.

SpeechRequest must use a Pydantic model validator with these exact rules:

~~~python
class SpeechRequest(BaseModel):
    model: ModelID
    input: str = Field(min_length=1, max_length=2000)
    voice: str | None = Field(default=None, max_length=100)
    language: str = Field(min_length=2, max_length=10)
    instructions: str | None = Field(default=None, min_length=1, max_length=1000)
    response_format: Literal["wav"] = "wav"
    speed: float = Field(default=1.0, ge=0.7, le=2.0)
    steps: int | None = Field(default=None, ge=5, le=12)

    @model_validator(mode="after")
    def validate_for_model(self) -> "SpeechRequest":
        if self.model == ModelID.SUPERTONIC:
            if self.voice not in {f"M{i}" for i in range(1, 6)} | {f"F{i}" for i in range(1, 6)}:
                raise ValueError("Supertonic voice must be M1-M5 or F1-F5")
            if self.instructions is not None:
                raise ValueError("Supertonic does not support instructions")
            return self
        if self.speed != 1.0 or self.steps is not None:
            raise ValueError("Qwen does not support speed or steps")
        if self.model == ModelID.QWEN_CUSTOM and not self.voice:
            raise ValueError("CustomVoice requires voice")
        if self.model == ModelID.QWEN_DESIGN:
            if not self.instructions or self.voice is not None:
                raise ValueError("VoiceDesign requires instructions and rejects voice")
        if self.model == ModelID.QWEN_CLONE and (
            not self.voice or not self.voice.startswith("voice_")
        ):
            raise ValueError("Voice clone requires a registered voice ID")
        return self
~~~
